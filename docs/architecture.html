백엔드 스킬 17종 backend/.claude/skills/

모두 같은 구조다: 규칙 → 적발 신호(Critical 머지 차단 · Important 참고 코멘트) → 체크리스트. 16종을 다 읽지 않는다 — "항상" 셋 + 고치는 파일에 맞는 것만.

항상 읽는 셋
kotlin-common판단 순서(IDE 경고 > 와이어 계약 > 읽기 쉬움 > 구조 > 적게 쓰기). Any·!!·var 금지, 판단이 든 람다 체이닝 대신 if/for, 데이터를 가진 타입이 계산도 소유, "없음"에 이름 주기
kotlin-module-layout멀티모듈 배치표와 단방향 의존. 소유 도메인 판정 4단계(주어 → 타입 생산자 → import 역전파 → 공용 재확인), 모듈 분리·접기 기준
kotlin-test한 메서드 = 한 기능. 조건이 다르면 메서드를 나눈다. 테스트 대상 목 대체·단언 약화 금지. BUILD SUCCESSFUL 은 증명이 아니다 — 실계수를 센다
기능 하나를 만들 때 — 아래에서 위로 쌓는 순서
1kotlin-entity본문 선언 + protected set, 변경은 행위 메서드로만. 애그리게이트는 루트를 통해서만. LAZY + EnumType.STRING
2kotlin-migration엔티티 변경 = 같은 커밋에 Flyway. 버전은 V<YYYYMMDDHHmm>(순번 금지), 적용된 파일 수정 금지, 삭제·개명은 배포 두 번
3kotlin-repository파생 쿼리로 의도 표현, 소유자 조건은 쿼리에. 상한 없는 findAll 금지, N+1 은 fetch join/@EntityGraph
4kotlin-implementFinder·Appender·Updater… 역할 하나씩. 엔티티↔도메인 모델 변환의 유일한 자리(internal 확장 함수). 트랜잭션 금지
5kotlin-domain-service흐름 조립 + 트랜잭션 경계 소유. 리포지토리 직접 접근 금지, 트랜잭션 안 외부 호출 금지. 도메인 간 통지는 이벤트 + @Async 리스너
6kotlin-dtoRequest/Response/Command/Result 접미사(Dto 금지). @field: 필수, 검증 대상 원시 타입은 nullable 로, ? 필드엔 사유 주석
7kotlin-controllerDTO 변환·인증 추출·ApiResponse 래핑 셋만. REST 경로(복수형·하이픈·동사 금지·중첩 한 겹), 상태코드 계약 201/204/200
상황에 따라 읽는 일곱
kotlin-style조건·분기·반복의 Kotlin 문법 — sealed 상태 표현(불가능한 상태를 타입에서 제거), else 없는 when, ?.let 람다 분기 금지, forEach 조기 종료는 for 로, 코루틴 CancellationException 재던지기
kotlin-error예외가 status·code·detail 을 스스로 가진다(ApiException) — 핸들러가 안 늘어남. 예외는 던지는 도메인이 소유. 403/404 구분으로 존재 여부를 유출하지 않는다
kotlin-authsecurity 의존성 = SecurityFilterChain 동반(아니면 헬스체크 401 → 컨테이너 재시작 반복). 인증은 필터, 인가는 도메인. 식별자를 요청에서 받지 않는다
kotlin-client외부 통신은 예외 없이 clients/client-*. 문서보다 실응답 먼저, 0건·실패로 기존 데이터 교체 금지, 30건 이상 호출은 사전 승인
kotlin-config설정은 쓰는 모듈이 소유(<모듈>.yml + import). 프로파일 5종. 비밀값은 환경변수만 — ${VAR:기본값} 금지
kotlin-logging레벨 기준은 "누가 봐야 하는가" — 4xx 는 ERROR 가 아니다. {} 치환, 예외는 마지막 인자로 통째로, traceId 로 요청 재구성
kotlin-api-docsREST Docs — 문서를 손으로 쓰지 않는다. 테스트가 스니펫을 만들고, 필드가 빠지면 테스트가 먼저 깨진다

프론트엔드 스킬 8종 frontend/.claude/skills/

항상 읽는 둘
frontend-common도메인 최상위 폴더·의존 방향(screens → hooks → services → api → lib 단방향), 파일 이름·export, 람다 관용구, 이름 규칙, 구축 순서, 리뷰 절차. src/user/ 가 살아 있는 정답 코드
frontend-styleTS/RN 문법 — 판별 필드(enum) union + assertNever 소진 검사, {count && ...} 숫자 렌더링 금지, ??/|| 구분, 훅 호출 위치, 리스트 key, 배열 원본 보존, 떠 있는 Promise
화면 하나를 만들 때 — 아래에서 위로
frontend-apitypes/+api/ — 서버 DTO 미러링(개명 금지), 엔드포인트 1:1, nullable 은 서버 코드를 열어 결정, ? 사유 주석
frontend-serviceservices/+enums/ — 상태코드 → 결과 enum/ServiceError 번역(2분법), 메시지 enum, 알림 단일 창구(notify)
frontend-hookshooks/ — 단일책임 훅·조립 훅(소비처별 그룹 반환), 3상태(ListState), useEffect 판정 넷
frontend-screenscreens/+components/ — 페이지 무상태(훅 1개 + JSX), 자기 표현 상태 예외, 모달 ref, 전역 확인 팝업, 스타일 분리
상황에 따라
frontend-liblib/ — HTTP 클라이언트는 앱에 하나, 래퍼 벗기기, 도메인 단어 금지
frontend-e2ePlaywright — 선택자 정책, 대기 규칙, 다이얼로그 함정. 기본은 page.route 모킹
리뷰 게이트 — 머지를 막는 것은 셋뿐이다: common/docs/code-review/rules.md 의 MUST 위반, 스킬 적발 신호의 Critical 항목, 그리고 이슈가 가리키는 스펙(specs/)과 어긋난 구현. 스타일 취향·요청 밖 개선 제안은 통과시키고 코멘트로만 남긴다. "변경 범위" 규칙은 특히 강하다 — 요청 밖 리팩터링을 곁들인 diff 는 내용이 옳아도 차단된다.
4 · Backend

백엔드 아키텍처 — 레이어와 차단선

Gradle 멀티모듈이라 참조 방향이 빌드로 강제된다. 규칙을 사람이 기억하는 대신 컴파일러가 지킨다.

모듈 배치

모듈담는 것
api유일한 부팅 모듈 — Application, ControllerAdvice, 전역 설정
core:core-<도메인>한 도메인 통째로 (api/ 컨트롤러·DTO + domain/ 서비스·모델·에러)
core:core-common · core-enum둘 이상의 도메인이 쓰는 것만 — 예외 베이스, 공유 enum
storage:db-core엔티티·리포지토리. 올려다볼 수 있는 것은 core-enum 하나뿐
clients:client-*외부 시스템 하나당 모듈 하나 — 통신 DTO 는 internal
support:*로깅·모니터링·도메인을 모르는 범용 함수

검증선: 백엔드 ./gradlew ktlintCheck unitTest · 프론트 npm run build(tsc strict 포함) — 노드가 커밋 전에 돌리는 최소선이다.

5 · Frontend

프론트엔드 아키텍처 — 도메인 최상위, 무상태 화면

도메인이 최상위 폴더고 그 아래가 계층이다 — src/<도메인>/{screens·components·hooks·services·api·lib·types·enums}. 한 도메인의 코드는 한 폴더 안에서 끝난다.

핵심 규칙

화면 하나는 types → api → enums → services → hooks → components → screen 순서로 만든다 — 백엔드의 만드는 순서와 같은 원리로, 아래에서 위로 쌓아야 상위 계층이 이미 있는 것을 조립한다.

규칙내용
도메인 최상위최상위에는 도메인과 app·common 만. 공용 안에 도메인 폴더를 파지 않는다
페이지 무상태화면 파일에 useState·useEffect 가 보이면 위반 — 자기 표현 상태 예외 셋만 허용
2분법예상된 비정상은 결과 enum 반환, 진짜 실패는 ServiceError throw. 불리언 반환 금지
메시지·알림사용자 문장은 전부 메시지 enum 에, 알림은 notify 한 창구로
플랫폼 분기iOS·Android·웹 한 코드 — 갈리면 파일 분기(.web.tsx)로 풀고 호출부는 구분을 모른다
