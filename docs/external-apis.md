# 외부 API 카탈로그

> **에이전트가 쓰고, 사람과 에이전트가 함께 읽습니다.** 외부 시스템을 붙이면 여기에 한 줄 추가합니다 (`backend/.claude/skills/kotlin-client`).

## 왜 이 문서가 있나

외부 연동은 시간이 지나면 **왜 그렇게 짰는지가 코드에 안 남는다.** 키가 어디서 오는지, 왜 매 요청이 아니라 하루 한 번인지, 막히면 무엇이 대신 나가는지 — 이걸 모르면 다음 사람이 처음부터 다시 조사한다.

그래서 붙일 때 한 줄 적는다. **막혔을 때 여기부터 본다.**

## 목록

| 이름 | 무엇을 주나 | 인증 | 호출 주기·한도 | 막히면 | 코드 |
|---|---|---|---|---|---|
| (아직 없음) | | | | | |

> 채우는 법 —
>
> **이름**: 부르는 쪽이 아는 이름(`결제`·`지도 검색`). 벤더명만 적지 않는다.
>
> **인증**: 키의 종류와 **어디서 주입되는지**(환경변수 이름). 키 값 자체는 절대 적지 않는다.
>
> **호출 주기·한도**: "요청마다" / "하루 1회 배치" / "일 1,000건". 한도가 설계를 정한다.
>
> **막히면**: 폴백 대상과 사용자에게 보이는 결과. "빈 목록 + 안내" 처럼 구체적으로.
>
> **코드**: `clients/client-<이름>` 모듈 경로.

## 붙이기 전에 확인한 것을 남긴다

실응답에서 확인한 것 중 **문서에 없던 것**을 그 API 항목 아래에 적는다. 다음 사람이 같은 것에 걸리지 않게.

적을 만한 것: 필드 이름이 문서와 다름 · 숫자가 문자열로 옴 · 좌표계·단위·시간대 · 페이징 방식 · 빈 결과의 모양 · 규격을 어긴 응답(제어문자 등)과 그 우회.

## 키를 새로 받았을 때

키 값은 저장소에 넣지 않는다. 환경변수로 주입하고(`kotlin-config`), 여기에는 **변수 이름만** 적는다.

키가 없으면 그 원천만 건너뛰고 나머지는 동작해야 한다 — 원천별 독립 게이트(`kotlin-client`).
