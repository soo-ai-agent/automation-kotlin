# 이슈 분석 md 문서 작성 규칙

이 스킬이 호출되면 아래 규칙에 따라 md 문서를 작성/수정한다.

## 1. 독자 기준

- **해당 내용을 모르는 사람도 이해할 수 있게** 쉬운 한국어로 풀어서 쓴다.

- 전문 용어(stderr, Debug 빌드, popen, journald 등)는 처음 나올 때 한 줄로 뜻을 설명한 뒤 사용한다.

- **비유를 사용하지 않는다.** (택배, 방아쇠, 우편함 같은 비유 금지) 사실과 동작 그대로를 순서대로 설명한다.

## 2. 문서 구조

- 불필요한 섹션은 만들지 않는다. 간결함이 우선.

- 관련 문서가 여러 개면 문서 상단에 상호 링크를 걸고, 상세본과 요약본을 분리 유지한다.

## 3. 근거와 출처

- **출처를 인용하는 모든 곳에 실제 코드 내용을 붙인다.** `파일명:행번호`만 쓰지 말고, 해당 코드 블록을 발췌해서 짧은 설명 주석과 함께 보여준다.

- 외부 소스(Qt 등)는 GitHub 등 열람 가능한 URL을 함께 적는다.

- **확정된 사실과 추정을 구분**한다. 장비/실환경에서 직접 확인한 결과에는 확인 날짜를 기록한다. 예: `**확정** — 장비에서 실행해 경고 확인 (2026-08-20)`

- 전제가 바뀌면(운영 환경, 수정 범위 등) 문서의 판정·조치도 함께 갱신해서 결론과 조치가 항상 일치하게 한다.

## 4. 표현 형식

- 표는 짧은 비교(프로그램별 판정, 조치별 효과)에만 사용한다. 설명은 표 밖의 문장으로 쓴다.

- 명령어를 제시할 때는 그 명령이 무슨 뜻인지, 결과를 어떻게 해석하는지 한 줄씩 덧붙인다.

- 절차는 시간순 번호 목록(①, 1. 등)으로 쓴다.

- 조치는 "근본 해결 / 권장 / 임시"로 등급을 구분하고, 임시 조치에는 한계(왜 임시인지)를 반드시 적는다.

## 5. 줄바꿈 (한 줄 글자수)

- 저장소 공통 md 규칙(CLAUDE.md)과 같다 — 한 줄에 문장을 이어 쓰다가 150자를 넘기 전에, 문장이 끝나는 지점에서 줄을 끊는다. 줄과 줄 사이는 빈 줄로 띄운다.

- 문장 중간에서 억지로 자르지 않는다. 한 문장이 150자를 넘으면 그대로 둔다.

- 코드 블록과 표, frontmatter, URL 은 예외다.

## 6. 작업 마무리

- 문서를 새로 만들거나 수정하면 SendUserFile로 사용자에게 전달한다.

- 무엇이 어떻게 바뀌었는지 요약해서 보고한다.
